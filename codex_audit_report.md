# MWT Codebase Audit Report

## 1. System Communication Findings

| File (FE) | File (BE) | Issue Description | Suggested Fix |
|---|---|---|---|
| `frontend/src/hooks/useProductoSelects.js` + `frontend/src/lib/api.js` | `backend/apps/productos/views.py` | `loadSubcategorias()` llama `productosApi.action("select_subcategorias/?categoria=...")`. El helper `resource.action()` siempre agrega `/` al final, generando una URL efectiva tipo `/api/productos/select_subcategorias/?categoria=CALZADO/`; el backend filtra `categoria_code=CALZADO/` y puede devolver vacío. | Agregar soporte formal para query params en `resource.action(name, id, body, params)` o llamar directamente `apiFetch("/productos/select_subcategorias/?categoria=...")` sin pasar el query dentro del nombre de acción. |
| `frontend/src/hooks/useInventarioSelects.js` + `frontend/src/lib/api.js` | `backend/apps/inventario/views.py` | Mismo patrón: `movimientosApi.action("select_motivos/?tipo_mov=...")` termina agregando `/` dentro del valor de query (`tipo_mov=.../`), rompiendo filtros exactos en `select_motivos`. | Reutilizar el fix anterior para query params. Añadir test unitario para asegurar que `resource.action("x", null, undefined, {a:"b"})` construya `/resource/x/?a=b`. |
| `frontend/src/lib/api.js` | `backend/apps/ai_hub/views.py` | `aiChatApi.selectAgents(params)`, `selectSkills(params)` y `selectInstructions(params)` aceptan `params`, pero los ignoran. El backend sí soporta `q`, `rol`, `category`, `scope`, etc.; por tanto autocompletes/búsquedas pueden traer los primeros 50 resultados sin filtrar. | Pasar los params a la URL: `/ai/agents/select/?${new URLSearchParams(params)}`. Evitar parámetros muertos en la firma si no se usan. |
| `frontend/src/components/transfers/TransferLiquidationPanel.jsx` | `backend/apps/transfers/views.py` | `confirmRemoveCost()` usa `fetch()` directo y no valida `resp.ok`. Si el backend responde 401/403/404/500, la UI elimina la línea localmente igual, dejando estado visual inconsistente con BD. | Usar `apiFetch`/`transferDetailApi.removeCost()` o validar `const resp = await fetch(...); if (!resp.ok) throw ...;` antes de `setCostLines`. |
| `frontend/src/hooks/useDashboardKpis.js` + `frontend/src/pages/Dashboard.jsx` | `backend/apps/analytics/views.py` | El hook del Dashboard dispara todos los endpoints de analytics aunque el render para cliente use `ClientDashboard`. Si el backend se corrige para devolver 403 en widgets CEO-only, el hook seguirá generando errores/ruido; actualmente además solicita datos que el cliente no necesita. | Dividir hooks: `useAdminDashboardKpis()` solo cuando `isAdmin`; `useClientDashboardData()` para cliente. No ejecutar fetches CEO-only antes del branch de rol. |

## 2. Security & Visibility Findings

| File / Route | Severity | Issue Description | Suggested Fix |
|---|---:|---|---|
| `backend/config/settings.py`, `.env.example`, `backend/apps/core/management/commands/seed_admins.py` | **Critical** | Hay secretos/defaults sensibles hardcodeados: `MINIO_ACCESS_KEY=admin`, `MINIO_SECRET_KEY=CHANGE-ME-MINIO-SECRET`, `DB_PASSWORD=mwt`, `BUILDER_PASSWORD=CHANGE-ME-BUILDER-PASSWORD`, `DEFAULT_PASSWORD="CHANGE-ME-SEED-ADMIN-PASSWORD"`, `SECRET_KEY="CHANGE-ME-DJANGO-SECRET"`. Aunque algunos sean defaults/dev, el repo mezcla valores reutilizables con credenciales reales plausibles. | Eliminar passwords reales del repo. Requerir env obligatoria en producción (`raise ImproperlyConfigured` si falta). Rotar credenciales MinIO/Builder/admin si fueron usadas. Usar `.env.example` con placeholders no reutilizables. |
| `backend/apps/core/json_error_middleware.py` | **High** | `_INCLUDE_TRACEBACK = os.environ.get("MWT_DEBUG_500", "1") == "1"` incluye tracebacks en `/api/` por defecto. En producción, si no se define la env, se filtran rutas, SQL/errores internos y query params al cliente. | Cambiar default a `"0"`. Condicionar tracebacks a `settings.DEBUG and MWT_DEBUG_500=1`. Sanitizar `query_params` en errores. |
| `backend/apps/storage/views.py` route `/api/storage/download/?key=...` | **High** | `download` usa `permission_classes=[AllowAny]` y trata la key como secreto. La propia documentación dice que la key UUID actúa como secret; esto es security-through-obscurity. Cualquier fuga de key permite descarga sin auth ni validación de tenant. | Preferir signed URLs con TTL o endpoint autenticado que valide ownership/alcance. Si se mantiene público, usar tokens largos aleatorios por objeto, expiración y revocación. |
| `frontend/src/context/RoleContext.jsx` vs `backend/apps/core/jwt_auth.py` | **High** | El backend trata como cliente cualquier rol `role_low.startswith("client_")`, pero el FE solo reconoce exactamente `client_b2b`, `client`, `cliente`. Un rol como `client_distributor` sería tratado como **ADMIN** en UI, mostrando rutas y acciones CEO-only. | Alinear lógica FE: `if (r.startsWith("client_") || ["client","cliente","client_b2b"].includes(r)) return "CLIENT";`. Añadir test con `CLIENT_*`. |
| `backend/apps/ai_hub/views.py` routes `/api/ai/agents/`, `/api/ai/skills/`, `/api/ai/instructions/` | **High** | Los comentarios dicen “gobernanza CEO-ONLY”, pero el guard solo bloquea roles cliente exactos. Roles internos no admin (`operator`, `viewer`, `finance`, `manager`) pueden leer/mutar catálogos de agentes/skills/instructions si están autenticados. | Reemplazar `_deny_ai_governance_for_client` por permiso positivo `IsCEOOrAdmin` para todos los métodos de gobernanza, no solo anti-client. |
| `backend/apps/ai_hub/views.py` | **Medium** | `_CLIENT_ROLES = {"client_b2b","cliente","client"}` no cubre roles `CLIENT_*`, pese a que otras capas sí lo hacen. Esto deja inconsistencias de aislamiento en AI Hub. | Usar helper central compartido (`is_client_like(role)`) con `startswith("client_")`. |
| `backend/apps/analytics/views.py` routes `/api/analytics/top_skus_margen/`, `/api/analytics/expediente_margin_scatter/`, `/api/analytics/_diag/` | **Critical** | Endpoints analytics devuelven márgenes, costos efectivos, revenue, muestras SQL/diagnóstico y no aplican guard CEO-only ni scope de cliente en esos métodos. `_diag` está documentado como debug-only pero solo requiere JWT. | Marcar analytics internos con permiso `IsCeoOrAdmin` o aplicar scope por `legal_entity_ids`. Eliminar o proteger `_diag` con staff/admin + `DEBUG`/env explícita. |
| `frontend/src/pages/Dashboard.jsx` + `frontend/src/hooks/useDashboardKpis.js` | **High** | Aunque el render oculta widgets CEO-only para cliente, el hook ya pidió datos de margen, top SKUs, exposición y scatter antes del branch visual. Esto rompe la pauta “gating en logic layer, no solo UI”. | Condicionar el hook por rol: no instanciar/fetchear analytics CEO-only cuando `isClient`. |
| `frontend/src/App.jsx` `AdminOnlyRoute` | **Medium** | `AdminOnlyRoute` significa realmente “not client”. Cualquier rol interno no admin pasa a rutas etiquetadas como CEO/admin-only (`/ai/governance`, `/historial-precios`, etc.). Algunos backend endpoints sí protegen; AI Hub governance no. | Renombrar a `InternalOnlyRoute` o implementar `AdminOnlyRoute` real con permisos del JWT (`superadmin/admin/ceo`). |

## 3. React Render Loops & Freeze Points

| File | Component / Line | Hook Pattern | Suggested Fix |
|---|---|---|---|
| `frontend/src/components/layout/AppLayout.jsx` | `AppLayout`, side effect during render near path-change block | Se ejecuta `abortInflightGets()` durante render cuando cambia `location.pathname`. Es un efecto externo no idempotente en fase de render; en Strict/Concurrent rendering puede abortar requests de forma inesperada o más de una vez. | Mover a `useEffect` o `useLayoutEffect` dependiente de `location.pathname`. Si se requiere antes del paint, usar `useLayoutEffect`, no render body. |
| `frontend/src/hooks/useDashboardKpis.js` | `useDashboardKpis` load Promise.all | El hook lanza ~15 requests en paralelo en mount. En React StrictMode dev se ejecuta dos veces; además se usa en Dashboard de cliente aunque no renderice los widgets admin. Puede saturar conexiones y causar “pantalla congelada” o loading lento. | Separar hooks por rol; añadir `AbortController` real por request; reducir endpoints con un backend bundle `/analytics/dashboard_bundle/` o lazy-load por widget visible. |
| `frontend/src/lib/api.js` | `apiFetch`, catch de `AbortError` sin signal explícito | En abort global de navegación, `apiFetch` devuelve `new Promise(() => {})`. Esto evita errores, pero deja promesas colgadas para callers que esperan finalizar loading si no tienen `isAlive` robusto. Puede dejar estados en `loading=true` en algunos flujos. | En vez de promesa infinita, lanzar/retornar un sentinel controlado (`AbortError`) y estandarizar callers para ignorarlo. O siempre pasar `AbortSignal` explícito desde hooks. |
| `frontend/src/components/CommandPalette.jsx` | `CommandPalette`, keydown effect deps `[filtered, active, onClose]` | `filtered` se reconstruye como array nuevo cada render, así que el listener global se desregistra/registra en cada pulsación y cada cambio de datos. No es loop infinito, pero es un punto de churn/performance. | Memoizar `filtered` con `useMemo` o depender de valores primitivos (`q`, `active`, longitudes) y usar refs para la lista actual. |
| `frontend/src/components/transfers/TransferLiquidationPanel.jsx` | `TransferLiquidationPanel`, effects sobre `transfer` objeto completo | Varios effects dependen de `transfer` completo y hacen múltiples `setState`/PATCH/onLiquidated. Si el padre recrea el objeto en cada refetch, dispara rehidrataciones completas, doble `load()` y puede generar parpadeos/overfetch. | Dependencias granulares: `transferId`, `transfer?.context_data`, `transfer?.legal_context`, `transfer?.liquidated_at`, `effectiveView`. Resetear refs por `transferId`. |
| `frontend/src/components/transfers/TransferLiquidationPanel.jsx` | `linesLen` effect | Hay un `useEffect(() => { load(); }, [linesLen])` adicional al `useEffect(() => { load(); }, [load])`, por lo que el montaje inicial hace doble carga. El comentario dice que se salta la primera vez, pero no hay guard efectivo. | Usar `useRef` `didMountRef` para omitir la primera ejecución o integrar `linesLen` en el `load` principal con debounce. |
